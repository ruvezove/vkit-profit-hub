# Profit Hub

Исходники находятся в `frontend/` и `backend/`. Команда сборки создаёт `dist/frontend/` и `dist/backend/`.

## Подготовка сервера

1. Разместите исходники в `~/vkit-profit-hub`. Сохраните существующий каталог `database/`. Перед первым запуском сделайте резервную копию командой SQLite `.backup`. Схема обновляется при первом старте с сохранением прежних аккаунтов.
2. Создайте `.env` по `.env.example` с правами `600`. Укажите актуальные секреты. Для SMTP задайте полный адрес Gmail в `SMTP_MAIL` и пароль приложения. Настройки старой версии из `~/.env.keys` больше не используются.
3. Настройте существующий HTTPS-прокси для `profit.pbk.kz` на `127.0.0.1:7700` с передачей исходного заголовка Host и корректного X-Forwarded-For. Приложение обслуживает интерфейс, API и callback по одному адресу. Укажите callback-адреса из `.env` в настройках Google и Яндекс.
4. Импортируйте файлы иконки, соберите приложение и проверьте конфигурацию oxmgr.

```sh
cd ~/vkit-profit-hub
umask 077
.runtime/bun --no-env-file install
.runtime/bun --no-env-file scripts/import-favicon.ts "$HOME/favicon"
.runtime/bun --no-env-file run build
oxmgr validate ./oxfile.toml
```

При переключении с прежней версии завершите только её процесс Bun, который занимает порт 7700, затем примените конфигурацию.

```sh
oxmgr apply ./oxfile.toml
oxmgr status profit-hub
curl -fsS http://127.0.0.1:7700/
```

После правки `.env` выполните `oxmgr restart profit-hub`.

## Вход и регистрация

- После регистрации и подтверждения почты войдите с паролем или через использованный при регистрации OAuth. Для регистрации через Яндекс и Google с внешним адресом требуется подтверждение почты. Существующие аккаунты не привязываются к OAuth автоматически по совпадению адреса.
- Открывайте ссылку подтверждения в том же браузере. `MAGIC_LINK_API_URI=API_URL` использует локальный адрес API. При переходе на публичный домен задайте `MAGIC_LINK_API_URI=API_URI`.
- Ученики со старым логином могут войти по нему до привязки почты. После подтверждения вход с паролем выполняется по почте.
- QR-код действует две минуты. Подтвердить вход может ученик с заполненным профилем. Код на двух экранах должен совпадать.
- Администратор видит значения `_CY` с маской. Пароль временного ученика задаётся в `TIMELESS_USER_PWD_CY`, доступ переключается через `TIMELESS_USER_ACTIVE`.

[Документация oxmgr](https://github.com/Vladimir-Urik/OxMgr/blob/master/docs/USAGE.md)

Для доступа из локальной сети задайте `APP_LAN_URL=http://192.168.85.134:7700/` в `.env`. Этот адрес добавляется к разрешённым источникам запросов API.

## Ключи доступа и сессии

После подтверждения почты и входа ученик может добавить ключ доступа в кабинете. WebAuthn работает на HTTPS-домене или localhost. Ключ привязан к имени сайта, поэтому локальный тестовый ключ не переносится на публичный домен.

Видимый кабинет опрашивает сервер каждые 45 секунд. Heartbeat возвращает HTTP 204, если профиль и список сессий прежние, либо присылает только изменившиеся данные. Активность продлевает срок сессии на 30 дней; сброс пароля отзывает прежние сессии.

## Погода и атмосферные эффекты

Open-Meteo используется для Павлодара. Сервер кэширует результат на 10 минут. Для проверки задайте `AMBIENT_TEST=true` и `AMBIENT_TEST_CURRENT=0` для снега, `1` для дождя, `2` для града или `3` для листьев. После изменения перезапустите приложение через oxmgr. Верните `AMBIENT_TEST=false` для реальной погоды.
